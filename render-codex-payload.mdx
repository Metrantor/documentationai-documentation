# `public.render_codex_payload(...)`

## Zweck

Diese Funktion rendert ein JSONB-Payload mit Codex-Einträgen in einen **strukturierten Textblock ohne äußeren Root-Tag**.

Sie ist dafür gedacht, aus einem Payload wie:

- `standard_codex`

- `super_codex`

- `chapter_codex`

- `world_codex`

einen Text zu erzeugen, der:

- pro Eintrag klar gegliedert ist

- aber **keinen äußeren Container-Tag** mehr enthält

Damit ist die Funktion für deinen neuen Prompt-Ansatz geeignet, bei dem die **äußeren Tags erst später über&#x20;**`{{platzhalter}}`**&#x20;im Prompt-Template gesetzt werden**.

---

## Was die Funktion rendert

Für jeden einzelnen Codex-Eintrag wird ein Block erzeugt in der Form:

```typescript
<codex_entry name="Eintragstitel">
Eintragstitel
Haupttext

Detail 1

Detail 2
</codex_entry>
```

Mehrere Einträge werden mit Leerzeilen getrennt.

---

## Was die Funktion bewusst **nicht mehr** macht

Die Funktion erzeugt **keine äußeren Container-Tags** mehr wie:

- `<codex>...</codex>`&#x20;

- `<super codex>...</super codex>`&#x20;

- `<chapter codex>...</chapter codex>`&#x20;

- `<world codex>...</world codex>`&#x20;

Diese Container sollen künftig erst im Prompt-Template über Platzhalter gesetzt werden, z. B.:

```typescript
<codex>
{{codex}}
</codex>
```

---

## Signatur

```typescript
public.render_codex_payload(
  p_payload jsonb,
  p_root_tag text default null
) returns text
```

---

## Parameter

### `p_payload jsonb`

Ein JSONB-Array mit Codex-Einträgen.

Jeder Eintrag kann typischerweise enthalten:

- `codex_title`&#x20;

- `codex_text`&#x20;

- `codex_details`&#x20;

Beispielstruktur:

```typescript
[
  {
    "codex_title": "Reaktor der Kalega",
    "codex_text": "Der Reaktor ist ein Monstrum.",
    "codex_details": [
      "Der Reaktor ist mattgrau.",
      "Der Reaktor glüht rot."
    ]
  }
]
```

---

### `p_root_tag text default null`

Historischer Parameter aus der älteren Rendering-Variante.

Er wird in der aktuellen Fassung **nicht mehr verwendet**, bleibt aber in der Signatur erhalten, damit bestehende Aufrufe nicht sofort umgebaut werden müssen.

Das bedeutet:

- &#x20;du kannst ihn weiterhin übergeben&#x20;

- &#x20;er beeinflusst das Ergebnis aber nicht mehr&#x20;

---

## Rückgabewert

### `text`

Ein zusammenhängender Textblock mit einem `<codex_entry>`-Block pro Payload-Eintrag.

Wenn das Payload leer oder `null` ist, liefert die Funktion einen leeren String.

---

## Interne Logik

Die Funktion arbeitet in drei Schritten:

### 1. Payload in Einträge zerlegen

Über:

```typescript
jsonb_array_elements(coalesce(p_payload, '[]'::jsonb)) with ordinality
```

werden die einzelnen JSON-Elemente samt Reihenfolge ausgelesen.

---

### 2. Pro Eintrag Textblock erzeugen

Für jeden Eintrag wird aufgebaut:

- `<codex_entry name="...">`&#x20;

- &#x20;Titel&#x20;

- &#x20;Haupttext&#x20;

- &#x20;Details&#x20;

- `</codex_entry>`&#x20;

Dabei gilt:

- &#x20;leere Felder werden ausgelassen&#x20;

- &#x20;Details werden nur verarbeitet, wenn `codex_details` ein Array ist&#x20;

- &#x20;Detaileinträge können Strings oder Objekte sein&#x20;

Bei Objekten werden diese Felder bevorzugt gelesen:

- `codex_detail`&#x20;

- `detail_text`&#x20;

- `text`&#x20;

---

### 3. Alle Eintragsblöcke zusammenführen

Die gerenderten Einträge werden in Ursprungsreihenfolge mit Leerzeilen getrennt zusammengefügt.

## Typische Verwendung im Gesamtsystem

Die Funktion wird typischerweise innerhalb von:

- `build_full_codex_context_json(...)`&#x20;

verwendet, um aus den Payloads:

- `standard_codex`&#x20;

- `super_codex`&#x20;

- `chapter_codex`&#x20;

- `world_codex`&#x20;

jeweils tagfreie, aber eintragsstrukturierte Textblöcke zu erzeugen.

Diese landen dann z. B. unter:

- `rendered.standard_codex`&#x20;

- `rendered.super_codex`&#x20;

- `rendered.chapter_codex`&#x20;

- `rendered.world_codex`&#x20;

und später weiter in:

- `prompt_blocks.codex`&#x20;

- `prompt_blocks.super_codex`&#x20;

- `prompt_blocks.chapter_codex`&#x20;

- `prompt_blocks.world_codex`&#x20;

---

## Warum diese Fassung sinnvoll ist

Diese Variante ist ein guter Kompromiss zwischen:

- **Struktur**&#x20;

- **Kürzbarkeit**&#x20;

- **Prompt-Flexibilität**&#x20;

### Vorteile

- &#x20;äußere Tags können später im Prompt-Template gesetzt werden&#x20;

- &#x20;pro Codex-Eintrag bleibt die semantische Einheit erhalten&#x20;

- &#x20;Kürzungen auf Blockebene sind leichter kontrollierbar&#x20;

- &#x20;die KI erkennt weiterhin, wo einzelne Codex-Einträge beginnen und enden&#x20;

## SQL-Statement

```typescript
```

```typescript
create or replace function public.render_codex_payload(
  p_payload jsonb,
  p_root_tag text default null
)
returns text
language sql
stable
as $function$
with entries as (
  select
    elem,
    ord
  from jsonb_array_elements(coalesce(p_payload, '[]'::jsonb)) with ordinality as t(elem, ord)
),
rendered as (
  select
    ord,
    array_to_string(
      array_remove(
        array[
          format('<codex_entry name="%s">', coalesce(elem->>'codex_title', '')),
          nullif(coalesce(elem->>'codex_title', ''), ''),
          nullif(coalesce(elem->>'codex_text', ''), ''),
          case
            when jsonb_typeof(elem->'codex_details') = 'array' then (
              select string_agg(detail_text, E'\n\n' order by didx)
              from (
                select
                  didx,
                  nullif(
                    case
                      when jsonb_typeof(d) = 'string' then trim(both '"' from d::text)
                      when jsonb_typeof(d) = 'object' then coalesce(
                        d->>'codex_detail',
                        d->>'detail_text',
                        d->>'text',
                        ''
                      )
                      else ''
                    end,
                    ''
                  ) as detail_text
                from jsonb_array_elements(coalesce(elem->'codex_details', '[]'::jsonb)) with ordinality as dd(d, didx)
              ) q
              where detail_text is not null
            )
            else null
          end,
          '</codex_entry>'
        ],
        null
      ),
      E'\n'
    ) as entry_text
  from entries
)
select coalesce(
  (
    select string_agg(nullif(entry_text, ''), E'\n\n' order by ord)
    from rendered
  ),
  ''
);
$function$;
```
